# MyQQ 服务端说明与测试指南

本文档面向**部署和运行服务端的人**（通常是组长 / 你自己）。讲清楚：服务端是什么、怎么启动、你需要做哪些事、怎么验证功能是否正常。

---

## 一、服务端是什么

MyQQ 采用 **C/S 架构**（客户端 / 服务端）：

- **服务端**：一个控制台程序 `MyQQServer.exe`。负责管理账号、好友、消息，并在客户端之间**转发聊天消息**。所有数据存进一个 SQLite 数据库文件 `myqq.db`。
- **客户端**：MFC 图形界面程序 `MyQQClient.exe`。用户在上面注册、登录、加好友、聊天。

一台机器跑服务端，局域网内的多台机器（或同一台机器开多个客户端）连上来通信。

> 通信范围：**仅局域网（LAN）**。不需要公网 IP、不需要端口映射。

---

## 二、服务端负责的功能

服务端不显示界面，它在后台响应客户端发来的每一条请求。支持的功能：

| 功能 | 客户端发来的命令 | 服务端做的事 |
|------|-----------------|-------------|
| 注册 | `REGISTER` | 在 Users 表新建账号，返回新用户 ID |
| 登录 | `LOGIN` | 校验账号密码，标记该用户在线 |
| 好友列表 | `FRIEND_LIST` | 查出该用户所有好友（含在线状态）返回 |
| 查找用户 | `SEARCH` | 按账号 / 昵称关键字查用户 |
| 添加好友 | `ADD_FRIEND` | 建立双向好友关系；对方在线则推送系统消息 |
| 发消息 | `CHAT` | **存库** + 若对方在线则**实时转发** |
| 登出 | `LOGOUT` | 标记该用户离线 |
| 查版本 | `VERSION` | 返回软件版本号 |
| 心跳 | `PING` | 返回 `PONG` |

关键点：**聊天消息一定会存进数据库**（`Messages` 表），无论对方在不在线；如果对方此刻在线，服务端会额外把消息**实时推送**过去（`CHAT_PUSH`）。

## 三、你需要做什么（部署步骤）

### 1. 编译服务端

服务端可以用 Visual Studio 或命令行编译。工程已提供 `CMakeLists.txt`。

**用 Visual Studio（推荐）**
1. 打开 VS，选「打开本地文件夹」，选中项目根目录 `myQQ`。
2. VS 会识别 `CMakeLists.txt`，自动配置。
3. 在上方目标下拉里选 `MyQQServer.exe`，点生成。

**或用命令行 CMake**
```bash
cd D:\Project\myQQ
cmake -B build -G "Visual Studio 17 2022"
cmake --build build --config Debug
```
生成的 `MyQQServer.exe` 在 `build/Debug/`（或 CMake 输出目录）。

### 2. 启动服务端

双击 `MyQQServer.exe`，或在命令行运行：
```bash
MyQQServer.exe          # 默认端口 6000
MyQQServer.exe 6001     # 指定端口
```
看到这行就是启动成功：
```
MyQQ 服务端启动，端口 6000，数据库 myqq.db
```
- **首次运行会自动创建数据库** `myqq.db`（在 exe 所在目录），并建好所有表。你不需要手动建库。
- 服务端启动后**保持这个窗口开着**，关掉窗口 = 关掉服务。

### 3. 查出服务端的局域网 IP（给客户端连接用）

在服务端机器上开命令行，运行：
```bash
ipconfig
```
找到「IPv4 地址」，形如 `192.168.1.20`。**把这个 IP 告诉所有要连接的客户端用户**——他们在登录界面填这个 IP。

> 如果服务端和客户端在**同一台机器**上测试，客户端 IP 填 `127.0.0.1` 即可。

### 4. 放行防火墙端口

第一次运行 `MyQQServer.exe` 时，Windows 防火墙通常会弹窗询问是否允许网络访问，**勾选「专用网络」并允许**。

如果没弹窗、或别的机器连不上，手动放行端口 6000：
- 控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口填 `6000` → 允许连接。

## 四、怎么测试功能

下面给两种测试路线：**单机快速自测**（一台机器）和 **局域网多机测试**（真实场景）。

### 路线 A：单机自测（最简单，先跑通）

在同一台机器上，服务端 + 两个客户端一起测：

1. 启动 `MyQQServer.exe`，保持窗口开着。
2. 启动第一个 `MyQQClient.exe`：
   - 服务器 IP 填 `127.0.0.1`，端口 `6000`。
   - 点「注册」，填账号 `alice`、密码 `123456`、昵称 `Alice`，提交。看到「注册成功」。
   - 回登录界面，用 `alice / 123456` 登录，进入主界面。
3. **再启动第二个** `MyQQClient.exe`（可以再双击一次 exe）：
   - 同样连 `127.0.0.1:6000`，注册 `bob / 123456 / Bob`，然后登录。
4. 在 alice 的主界面：查找框输入 `bob`，点「查找/添加」，提示找到并询问是否加好友，选「是」。
5. 点「刷新」，alice 的好友列表出现 bob。
6. 选中 bob，点「打开聊天」（或双击），在聊天窗口输入「你好」发送。
7. **切到 bob 的客户端**：bob 会弹出 / 收到来自 alice 的消息 —— 这就验证了**实时转发**。
8. bob 回一条，alice 这边也应实时收到。

### 路线 B：局域网多机测试（真实场景）

1. 在**服务端机器**上启动 `MyQQServer.exe`，用 `ipconfig` 查到 IP，比如 `192.168.1.20`，确认防火墙放行 6000。
2. 把 `MyQQClient.exe` 拷到**另外几台**同一局域网的机器上。
3. 每台客户端登录界面：**服务器 IP 填 `192.168.1.20`**，端口 `6000`。
4. 各自注册不同账号、登录、互相加好友、聊天。
5. 验证：A 机发消息，B 机能实时看到。

> 前提：所有机器连的是**同一个路由器 / 同一个局域网**（同一 WiFi 也行）。

### 功能验收清单

对照这张表逐项打勾，就是完整的功能测试：

- [ ] 服务端能启动，自动生成 `myqq.db`
- [ ] 客户端能连上服务端（IP / 端口正确）
- [ ] 点「查询本机」能显示本机主机名和 IP
- [ ] 注册新账号成功，重复账号会被拒绝
- [ ] 正确密码能登录，错误密码被拒绝
- [ ] 能查找到其他用户并添加为好友
- [ ] 好友列表能显示，能刷新，能看到在线/离线状态
- [ ] 打开聊天窗口能发消息
- [ ] 对方在线时能**实时收到**消息
- [ ] 聊天窗口在程序目录下自动生成了**聊天记录文件**（`logs/` 目录）
- [ ] 右键窗口能查询软件版本

## 五、怎么确认数据真的存进去了

服务端用的是 SQLite 数据库文件 `myqq.db`。如果你想亲眼确认注册的账号、发的消息都存下来了，可以用任意 SQLite 工具查看，或用命令行（若装了 sqlite3）：

```bash
sqlite3 myqq.db "SELECT UserId, Account, NickName FROM Users;"
sqlite3 myqq.db "SELECT SenderId, ReceiverId, Content, SendTime FROM Messages;"
```
能看到你注册的用户和发过的每一条消息（含时间戳）。

## 六、常见问题排查

| 现象 | 可能原因 / 解决 |
|------|----------------|
| 客户端提示「连接服务端失败」 | 服务端没启动 / IP 或端口填错 / 防火墙没放行 6000 |
| 别的机器连不上，本机能连 | 防火墙没放行；或不在同一局域网；确认用的是服务端的**内网 IP**不是 `127.0.0.1` |
| 消息发出去对方收不到 | 对方是否已登录并在线；离线时消息只存库不推送，对方下次相关操作后才可能看到 |
| 服务端窗口一闪就关 | 端口被占用（换个端口 `MyQQServer.exe 6001`）；或 `myqq.db` 被占用 |
| 中文显示乱码 | 确认客户端源码用 `/utf-8` 编译（工程已配置） |

## 七、给答辩 / 报告的一句话总结

> MyQQ 是一个基于 TCP 的 C/S 架构局域网聊天工具。服务端用 C++ 多线程处理并发连接，数据持久化到 SQLite；客户端用 MFC 实现图形界面。消息经服务端存库后，对在线用户实时转发，实现了注册、登录、好友管理、即时聊天等完整功能。
