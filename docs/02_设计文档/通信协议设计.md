# MyQQ 通信协议设计

## 1. 传输层
- 协议：**TCP**（Winsock 2），阻塞式，局域网内通信。
- 端口：默认 `6000`（`myqq::kDefaultPort`）。
- 连接方式：客户端输入服务端的**局域网 IPv4**（如 `192.168.x.x`）+ 端口连接。
- 编码：UTF-8 文本。

## 2. 报文格式
一条报文一行，以 `\n` 结束。字段以 `|` 分隔：
```
CMD|arg1|arg2|...\n
```
- 首字段为命令名。
- 由 `src/common/Message.cpp` 的 `Pack` / `Unpack` 负责序列化与解析。
- 服务端做了粘包/半包处理（`TcpSocket::RecvLine` 按 `\n` 切分缓冲）。
- **凡是用户文本字段（记为 `xxxB64`）一律 Base64URL(UTF-8) 编码**：账号、密码、昵称、搜索词、验证信息、签名、头像、聊天内容、时间等。数字 ID、状态码、命令名保持明文。这样 `|`、换行、中文、emoji 都不会破坏报文。服务端对解码后长度做校验（聊天≤2000、验证≤200、昵称≤50 字节）。
- 服务端只信任连接自身登录态 `curUser`，客户端不再传自己的 ID。

## 3. 命令一览

### 3.1 请求（客户端 → 服务端）

| 命令 | 格式 | 说明 |
|------|------|------|
| REGISTER | `REGISTER\|accountB64\|passwordB64\|nickB64` | 注册 |
| LOGIN | `LOGIN\|accountB64\|passwordB64` | 登录 |
| LOGOUT | `LOGOUT` | 登出当前连接，保留 TCP 以便切换账号 |
| SEARCH | `SEARCH\|keywordB64` | 按账号/昵称模糊查找（排除自己） |
| ADD_FRIEND | `ADD_FRIEND\|targetId\|verifyB64` | 发送好友申请（不直接建立好友） |
| FRIEND_ACK | `FRIEND_ACK\|requestId\|accept(0/1)` | 接受/拒绝收到的好友申请 |
| FRIEND_SYNC | `FRIEND_SYNC` | 登录后同步离线待处理申请和未读结果 |
| FRIEND_RESULT_SEEN | `FRIEND_RESULT_SEEN\|requestId` | 标记申请结果已读 |
| FRIEND_LIST | `FRIEND_LIST` | 获取好友列表 |
| CHAT | `CHAT\|targetId\|clientMsgId\|contentB64` | 发送聊天消息 |
| CHAT_HISTORY | `CHAT_HISTORY\|peerId\|beforeMsgId\|limit\|requestId` | 拉取历史（分页，beforeMsgId=0 取最新） |
| GET_PROFILE | `GET_PROFILE` | 读取自己资料 |
| UPDATE_PROFILE | `UPDATE_PROFILE\|nickB64\|gender\|starId\|bloodId\|signB64\|avatarB64` | 更新自己资料 |
| VERSION / PING | `VERSION` / `PING` | 版本 / 心跳 |

### 3.2 响应（服务端 → 客户端）

| 响应 | 格式 | 说明 |
|------|------|------|
| REGISTER_RESP | `REGISTER_RESP\|status\|payload` | 0 成功(payload=新QQ号)，4 账号已存在 |
| LOGIN_RESP | `LOGIN_RESP\|status\|payload` | 0 成功(payload=QQ号)，2 账号或密码错误 |
| LOGOUT_RESP | `LOGOUT_RESP\|status` | 登出结果 |
| SEARCH_RESP | `SEARCH_RESP\|status\|count\|[id,accountB64,nickB64,status]*` | 命中列表 |
| ADD_FRIEND_RESP | `ADD_FRIEND_RESP\|status\|requestId\|state` | 0 已发送申请，4 已是好友/重复 |
| FRIEND_ACK_RESP | `FRIEND_ACK_RESP\|status\|requestId\|decision` | 处理结果 |
| FRIEND_SYNC_RESP | `FRIEND_SYNC_RESP\|status\|pending\|result` | 同步计数 |
| FRIEND_LIST_RESP | `FRIEND_LIST_RESP\|status\|count\|[id,accountB64,nickB64,status]*` | 好友列表 |
| CHAT_ACK | `CHAT_ACK\|status\|clientMsgId\|msgId\|sendTimeB64` | 入库成功后回执（失败时 payload 为错误信息） |
| CHAT_HISTORY_BEGIN/ITEM/END | 见下 | 分页历史 |
| GET_PROFILE_RESP / UPDATE_PROFILE_RESP | | 资料读写结果 |

历史分页按多行返回（消息尾部统一带 kind 与文件元数据）：
```
CHAT_HISTORY_BEGIN|status|requestId|peerId|count
CHAT_HISTORY_ITEM|requestId|msgId|from|to|timeB64|kind|contentB64|fileId|nameB64|size   (0..count 行)
CHAT_HISTORY_END|requestId|hasMore|nextBeforeMsgId
```

### 群聊
```
GROUP_CREATE|nameB64|requireApproval      → GROUP_CREATE_RESP|status|groupId（群号 20 万起）
GROUP_SEARCH|keywordB64                    → GROUP_SEARCH_RESP|status|count|[gid,nameB64,memberCount,requireApproval]*
GROUP_LIST                                 → GROUP_LIST_RESP|status|count|[gid,nameB64,role]*
GROUP_MEMBERS|groupId                      → GROUP_MEMBERS_RESP|status|groupId|count|[uid,nickB64,role]*
GROUP_APPLY|groupId                        → GROUP_APPLY_RESP|status|state(joined/pending)
GROUP_INVITE|groupId|friendId              → GROUP_INVITE_RESP|status
GROUP_INVITE_ACK|reqId|accept              → GROUP_INVITE_ACK_RESP|status（被邀请人同意/拒绝）
GROUP_APPROVE|reqId|accept                 → GROUP_APPROVE_RESP|status（群主审批）
GROUP_SYNC                                 → 登录补发 GROUP_INVITE_PUSH/GROUP_APPLY_PUSH/GROUP_RESULT_PUSH
GROUP_RESULT_SEEN|reqId
GROUP_CHAT|groupId|clientMsgId|contentB64  → GROUP_CHAT_ACK|status|clientMsgId|msgId|timeB64
GROUP_HISTORY|groupId|before|limit|reqId   → GROUP_HISTORY_BEGIN/ITEM/END
```
群消息推送 / 历史项主体：`msgId|groupId|senderId|senderNickB64|timeB64|kind|contentB64|fileId|nameB64|size`
- 推送：`GROUP_PUSH|<上述>`；历史：`GROUP_HISTORY_ITEM|reqId|<上述>`
入群状态机：申请(自己)或邀请(成员拉好友)→ 被邀请人同意(邀请场景)→ 群主审批(需审批的群)→ 入群。群消息/历史/成员需 `IsGroupMember`；审批需群主；邀请需成员且被邀者是好友。

### 查看他人资料
```
VIEW_PROFILE|userId → VIEW_PROFILE_RESP|status|userId|accountB64|nickB64|gender|starId|bloodId|signatureB64|avatarB64
```
权限：本人 / 好友 / (对方 Visibility==0 且同群) 才可看，否则 status=2。`UPDATE_PROFILE` 末尾可选追加 `visibility`（1=仅好友可见）。

### 文件/图片传输（分块，kind：0文本 1图片 2文件；单文件 ≤ 20MB，每块 2048 原始字节）
上传（客户端生成 token，无逐块回执；scope=0 好友 1 群，targetId 为好友或群号）：
```
FILE_BEGIN|targetId|token|kind|nameB64|totalBytes|scope   → FILE_BEGIN_ACK|token|status
FILE_CHUNK|token|seq|dataB64                       （无回执）
FILE_END|token                                     → FILE_DONE|token|status|msgId|sendTimeB64
```
下载：
```
FILE_GET|fileId|requestId  → FILE_DATA_BEGIN|requestId|status|kind|nameB64|totalBytes
                             FILE_DATA_CHUNK|requestId|seq|dataB64   (多行)
                             FILE_DATA_END|requestId|status
```
文件在服务端存于 `server/data/files/<fileId>`；图片/文件消息也进入 `CHAT_HISTORY`（TypeId 5/6）。

### 3.3 服务端主动推送

| 推送 | 格式 | 触发 |
|------|------|------|
| CHAT_PUSH | `CHAT_PUSH\|msgId\|from\|to\|timeB64\|kind\|contentB64\|fileId\|nameB64\|size` | 给在线用户实时下发消息（含图片/文件） |
| FRIEND_REQUEST_PUSH | `FRIEND_REQUEST_PUSH\|requestId\|senderId\|accountB64\|nickB64\|verifyB64\|timeB64` | 收到好友申请 |
| FRIEND_RESULT_PUSH | `FRIEND_RESULT_PUSH\|requestId\|receiverId\|receiverNickB64\|decision\|timeB64` | 申请被接受/拒绝 |

## 4. 状态码（`myqq::Status`）
| 值 | 含义 |
|----|------|
| 0 | 成功 |
| 1 | 参数错误/失败 |
| 2 | 认证失败 |
| 3 | 未找到 |
| 4 | 已存在 |
| 5 | 服务器错误 |

## 5. 典型交互时序

### 登录并接收消息
```
Client(bob)                     Server                    Client(alice)
   | LOGIN|bob|456                 |                            |
   |----------------------------->| 校验DB, 登记在线            |
   |<-----------------------------| LOGIN_RESP|0|10002          |
   |                              |         LOGIN|alice|123     |
   |                              |<----------------------------|
   |                              |         CHAT|10001|10002|hi |
   |                              |<----------------------------|
   |                              | 存Messages表                |
   |<-----------------------------| CHAT_PUSH|10001|hi          |
   |  (接收线程显示消息)           |---------------------------->| CHAT_ACK|0
```

## 6. 客户端实现要点
- 接收线程把整行消息放入队列，只 `PostMessage(WM_NET_MESSAGE)` 唤醒当前阶段窗口；窗口 `DrainMessages()` 取出。切换窗口不会丢消息。
- 登录阶段由登录窗口做唯一网络 owner，登录后由主窗口做唯一 owner。个性化设置/注册/好友申请等模态窗体由 owner 转发对应响应，不再各自抢占。
- **聊天历史以服务端 SQLite 为准**：打开聊天窗口发 `CHAT_HISTORY` 拉最近 50 条，按 `msgId` 去重并升序显示，展示服务端原始时间。`ChatLogger` 仅作本地备份，不参与历史恢复。
- **加好友是申请制**：`ADD_FRIEND` 只创建待处理申请；对方 `FRIEND_ACK` 接受后才双向建立好友；离线申请/结果登录后由 `FRIEND_SYNC` 补发。
- 已用两客户端端到端验证：中文昵称、含 `|`/换行的验证信息、含 `|`/emoji 的聊天、历史恢复、切换账号全部正常。
