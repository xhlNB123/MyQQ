# MyQQ 部署与发布说明

## 为什么直接复制旧 exe 会失败

- `build/MyQQServer.exe` 是早期 MinGW 构建，依赖 `libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`；只复制 exe 到别人电脑会在进入 `main` 前失败。
- `src/client/MyQQClient/x64/Debug/MyQQClient.exe` 是 Debug MFC 程序，依赖 `mfc140ud.dll`、`ucrtbased.dll` 等开发机调试 DLL。它只适合在装有 Visual Studio 的电脑调试，不能发给最终用户。
- `.sln` 本身不会修复编码；Visual Studio 只是构建并运行了正确的 Debug 文件，同时提供了开发运行库。当前 GUI 工程已使用 Unicode、`/utf-8` 和 RC 65001，若发布版界面仍“乱码”，通常说明发错了 exe。

## 一键生成可分发压缩包

### 构建机要求

Windows 10/11 x64、Visual Studio 2022，并在 VS Installer 安装：

1. “使用 C++ 的桌面开发”
2. 最新 v143 x64/x86 生成工具
3. Windows 10/11 SDK
4. “适用于最新 v143 生成工具的 C++ MFC”

在项目根目录运行 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package-windows-x64.ps1
```

脚本会自动：

- 用 MSVC x64 Release 静态 CRT 构建服务端；
- 用 Release x64 静态 MFC/CRT 构建 GUI 客户端；
- 检查两个 exe 的架构、子系统和依赖；
- 阻止 Debug/MinGW/运行库依赖、PDB、数据库、日志进入包；
- 生成 `dist/MyQQ-1.0.0-windows-x64.zip` 和 `.sha256` 校验文件。

不要手工从 `Debug/`、`build/` 或 VS 中间目录挑 exe 打包。

## 发布包结构

```text
MyQQ-1.0.0-windows-x64/
├─ README-部署.md
├─ server/
│  ├─ MyQQServer.exe
│  ├─ Start-Server.cmd
│  └─ database/schema_sqlite.sql
├─ client/MyQQClient.exe
└─ docs/
   ├─ 客户端使用说明书.md
   └─ 服务端说明与测试指南.md
```

数据库在首次运行时创建于 `server/data/myqq.db`；客户端聊天记录写入 `client/logs/`。两者都相对 exe 定位，不受快捷方式或终端当前目录影响。

## 接收方使用方法

1. 校验 zip 的 SHA-256（可选但推荐）。
2. **完整解压**到桌面、文档等可写目录；不要直接在压缩软件内运行。
3. 双击 `server/Start-Server.cmd` 并保持窗口打开。
4. 双击 `client/MyQQClient.exe`。本机测试填 `127.0.0.1:6000`；局域网测试填服务端窗口显示的内网 IPv4。
5. 防火墙或 SmartScreen 弹窗时：服务端允许“专用网络”；SmartScreen 可先核对 SHA-256 再继续运行。

最终用户不需要打开 `.sln`，也不需要安装 Visual Studio、MFC、MinGW 或 VC++ Redistributable。

## 发布验收

至少在一台未安装 Visual Studio/MinGW 的 Windows 10/11 x64 电脑测试：

- 双击服务端和客户端均能启动；
- 中文界面正常；
- 双开客户端能注册、登录、加好友、聊天、修改个人资料；
- 服务端重启后数据仍在 `server/data/myqq.db`；
- 客户端日志出现在 `client/logs/`；
- 从中文且带空格的目录启动也正常。

若缺少 schema，服务端应明确显示期望路径并退出；若 6000 被占用，`Start-Server.cmd` 会保留窗口和退出码，不会一闪而过。
